工具表 登记在 registry + tool_schemas.json

read / write / edit
仓库文件。read/write 只读锁；同路径 write 串行。
bash
本机命令。8k 截断。拦 rm -rf。无路径锁。
grep
有 rg 用 rg。第一页 20 条；全文在 tools_result/grep；cursor 翻页。
web_search
有 PERPLEXITY_API_KEY 走 Search API，否则 DDG 子进程。结果仍进 jsonl。
web_fetch
GET + 转文本。全文落盘；jsonl 只留路径和约 30 行预览。拦内网。

已经完成、但还要工程化

点为什么还不算收口
压缩阈值 回合结束进场 60% 写在代码里；注释/文档曾经按 80% 写。schema（两类 meta）应冻，数字可继续拧，但要对齐。
人设怎么发出去 SYSTEM_PROMPT 启动时读死。skill 清单没有地方接。loop 里两行胶水兼着拼 prompt。
web_search 结果 snippet 列表仍整段进 jsonl。一般不肥；和 fetch 不对称。DDG 是非官方扒页，当尽力。
bash 大输出 只靠 8k 截断，没有像 fetch 那样落盘再读。
SwiftAgent 外壳 reply(memory, …)、ExecutionDependencies 几乎空。CLI 走 _run_loop。不影响转圈，命名会和以后的 memory 撞车。
fetch 第二轮 4 次 fetch 后要再 grep/read 才看正文。换来的是 jsonl 不再被导航栏撑爆。这是产品选择，不是漏做。

还没做的模块

skill
磁盘上的 SKILL.md + 脚本。prompt 只挂名字和一句话，正文用 read，脚本用 bash。 不要做成第六类核心工具。先要有「人设后面拼清单」那一步。
跨会话 memory
不是 jsonl，也不是压缩摘要。第一种形态就是仓库里的文件（模型自己维护）。 检索/自动抽取是后面的新模块，别塞进 compaction。
插件 / extension
权限弹窗、SSH 换执行位置、MCP。改的是 loop 怎么跑工具，不是说明书。现在不必造。
浏览器 / 桌面 computer use
fetch 是静态 GET。Yahoo 重 JS、登录墙会失败。浏览器更像 skill 或以后的真工具，现在不做。

建议的下一刀顺序

#做什么为什么现在
1 冻压缩记账格式，把进场比例和文档写成同一数字 后面 skill/memory 不要再发明第三种「改历史」。
2 抽出「拼这一枪的 system」：yaml + 以后的 skill 清单 不动 loop 转圈；skill 才有地方接。
3 skill（扫目录、清单进 system，不进工具表） 外挂能力的正道。搜网已经是工具，skill 管流程和可选包。
4 memory 先当仓库文件，不单独立项 真要检索再开模块。别和 jsonl、摘要混。
